# DEV.md — bioR Developer Guide

Everything needed to build, verify, and extend the bioR site. The site itself is static HTML/CSS/vanilla JS; all data, figures, and example outputs are generated by R scripts in `tools/`.

For design/curriculum background (Chinese), see `docs/01…08`. For the finished-site audit trail, see `docs/audit/phase0-audit.md`.

---

## 1. Prerequisites

| Tool | Version | Notes |
| --- | --- | --- |
| R | 4.5.x | `build-all.sh` auto-detects `Rscript`; on this dev machine it lives at `C:\Program Files\R\R-4.5.2\bin` |
| Node.js | ≥ 18 | build builders and validator |
| Python | 3.x | static/browser audit helpers (standard library only) |
| Git | any recent | LF enforced via `.gitattributes` |

**One-time R setup** — installs all packages into the project-local library `tools/rlib/` (never the global library):

```bash
Rscript tools/setup-packages.R
```

This includes tidyverse-stack packages plus the advanced stack: `lme4`, `lmerTest`, `survival`, `DHARMa`, `pheatmap`, `vegan`, `hexbin`, `BiocManager`, and Bioconductor's `edgeR`, `limma`, `DESeq2`, `apeglm`, `clusterProfiler`.

> CI note: `.github/workflows/validate.yml` runs `tools/build-all.sh` on push, but currently installs only the core CRAN set — the Bioconductor packages used by ch15–18 examples are not installed there yet. Extend that workflow if CI turns red on the advanced chapters.

## 2. Build everything

```bash
bash tools/build-all.sh
```

The 8 steps, in order (order matters):

| # | Step | What it does |
| --- | --- | --- |
| 1 | `generate-data.R` | Regenerates the 9 teaching datasets from a fixed seed (20261027) |
| 2 | `validate-data.R` | Hard data contract checks (dims, NA placement, factors, censoring) |
| 3 | `render-figures.R` | Renders the 18 registered figures (SVG + PDF) and `manifest.json` with sha256 |
| 4 | `render-examples.R` | Runs every `tools/examples/chNN-ex-NN.R` in an isolated `Rscript --vanilla` child, writes `expected/*.txt`, injects outputs into chapter HTML |
| 5 | `check-examples.R` | **Hard gate**: byte-compares fresh outputs vs `expected/` and the HTML blocks. `ALL PASS` required |
| 6 | `collect-errors.R` | Actually triggers the 50 triage errors in R and writes `tools/errors/errors.json` |
| 7 | Node builders | `build-data-previews` → `build-triage-data` → `build-search-index` → `build-chapter-scripts` → `build-cheatsheet-cards` → `build-clinic-cards`. Previews/triage **must** run before search-index or the index meta goes stale |
| 8 | `validate.mjs` | Site-wide validator: links/anchors, code-block escaping, JSON blocks, duplicate ids, chapter structure, figure + data manifests, offline rules, CSS token discipline |

**Delivery gate:** `validate: 0 error(s), 0 warning(s)` **and** `check-examples: ALL PASS`.

Running single steps:

```bash
Rscript tools/generate-data.R
Rscript tools/check-examples.R
node tools/validate.mjs
node tools/build-search-index.mjs
```

## 4. Project structure

```text
assets/
├─ css/        tokens / base / layout / components / pages / print
├─ js/         bior-core, nav, search, progress, mastery, listing, stepper,
│              quiz, toc, presenter, data-preview, glossary + pages/* + data/*
├─ data/       generated teaching CSVs + data dictionary (simulated, fixed seed)
├─ figures/    chapters/*.svg|pdf  (rendered from the registry) + manifest.json
└─ scripts/    chNN.R per-chapter download scripts (assembled by a builder)
chapters/      18 chapter pages; example outputs are injected by render-examples
data/, figures/  chapter deliverables (what a student would hand in)
docs/          01…08 design/engineering docs (Chinese) + audit/ audit log
tools/         R pipeline, Node builders, validators, audit harness
tools/examples/    chNN-ex-NN.R source of truth for every on-page output
tools/errors/      errors.json — the only source for triage cards
```

Key engine facts (full contracts in `docs/05-engineering.md`):

- Global namespace is `window.BIOR`; data files set `COURSE_TOC`, `BIOR_SPECIALS`, `BIOR_CHEATSHEETS`, `BIOR_DATASETS`, `BIOR_TRIAGE`, `BIOR_CLINIC`, `BIOR_BIOINFO`, `BIOR_GLOSSARY`, `BIOR_CONFIG`, `BIOR_SEARCH_INDEX`.
- Load order per page: `theme-init` → CSS → data files → `bior-core` → `nav`/`progress` → feature scripts → `pages/*`.
- Every page must keep working from `file://`: **no fetch, no ES modules, no CDN, no webfonts.**

## 5. Data, figures, examples — the honesty pipeline

### Data
- `tools/generate-data.R` writes the 9 datasets (pika physiology, repeated measures, survival, RNA-seq counts/metadata/annotation, plate reader, Excel lab log).
- NA placement, outliers, and censoring are deliberate teaching points and asserted by `validate-data.R`.

### Figures
- `tools/figures/registry.R` is the single source of truth (id, chapter, script, size, alt, caption).
- Each `tools/figures/fig_*.R` exports `build_figure(data)` returning a ggplot; `render-figures.R` applies `theme_bio()`, renders SVG (svglite) + PDF, and hashes everything into `manifest.json`.
- Budgets: SVG ≤ 150 KB; captions must contain `图 N.N` and `n = …`; Okabe–Ito palette only (`tools/figures/palettes.R`).

### Example outputs
- Every on-page `R console` block comes from `tools/examples/chNN-ex-NN.R`, run in an isolated child process by `render-examples.R`.
- `check-examples.R` re-runs them and byte-compares against `expected/*.txt` **and** the injected HTML — nothing on the site may be invented by hand.
- Authoring rules: ≥ 5 example cards per chapter, ≥ 2 with `.ex-steps` (line-by-line stepper), ≥ 1 research-task deliverable.

### Triage errors
- `tools/collect-errors.R` provokes each error live and stores raw message + minimal repro. Never hand-edit triage cards; edit the recipe and re-collect.

## 6. Static-card builders

`cheatsheets.html`, `clinic.html`, and `triage.html` render cards at **build time** (Node builders writing static HTML between markers), so the pages work without JS. The JS on those pages only filters/searches/highlights.

Markers: `<!-- CHEAT_CARDS_START/END -->`, `<!-- CLINIC_CASES_START/END -->`, `<!-- CLINIC_FLAGS_START/END -->`. Text fields in data files are entity-encoded; don't un-escape them in the data files.

## 7. Audit harness

All three tools are read-only and expect the dev server on `127.0.0.1:8765`.

```bash
python tools/dev-server.py

python tools/audit-static.py
#   29 pages: metadata, heading outline, duplicate ids, img alt/dimensions,
#   button/input accessibility, offline resources, leftover markers,
#   chapter rule: >= 2 .ex-steps per chapter

node tools/audit-browser.mjs /tmp/bior-audit
#   headless Chrome over all 29 pages × desktop 1440 / mobile 390:
#   console + resource errors, broken images, document overflow,
#   content-count expectations (18 chapters / 36 cards / 50 errors / …),
#   screenshots per viewport. Filter with BIOR_ONLY=page.html

node tools/audit-interactions.mjs
#   77 DOM-driven assertions across 13 pages: Ctrl+K palette, filters/reset,
#   red-flag screener, workflow tabs, decision tree, workbench persistence,
#   mastery, self-test, quiz feedback, stepper, matrix row labels
```

A release is green when: build-all exit 0, validator 0/0, check-examples ALL PASS, all three audits report zero issues, and `file://` spot checks work.

## 8. Conventions

- **Commit messages: English** (e.g. `fix: unescape <- in bioviz recipe card`, `docs: expand figure pipeline notes`).
- **README.md is English-primary**; keep the Chinese mirror in `README.zh-CN.md` in sync. `DEV.md` is English-only.
- Site prose is Chinese; figure labels/statistical symbols are English (journal-ready graphics).
- Line endings are LF for everything (`.gitattributes`); binaries are marked.
- Never modify `cpp_website/` — it is a read-only reference project.
- Design docs in `docs/` stay Chinese; DEV.md is the English entry point for developers.
- New pages/features follow the per-page audit rule: static audit + browser audit + interaction checks before merge.

## 9. Common tasks

```bash
# Rebuild one dataset + everything downstream
bash tools/build-all.sh

# Only re-render figures after editing a fig script
Rscript tools/render-figures.R

# Only re-check example outputs
Rscript tools/check-examples.R

# Add a cheat sheet: edit assets/js/data/cheatsheets-data.js, then
node tools/build-cheatsheet-cards.mjs && node tools/validate.mjs

# Add a triage error: add a recipe in tools/collect-errors.R, then
Rscript tools/collect-errors.R && node tools/build-triage-data.mjs && node tools/build-search-index.mjs
```

## 10. Release checklist

1. `bash tools/build-all.sh` → exit 0, validator 0/0, `check-examples: ALL PASS`.
2. `python tools/audit-static.py` → 0 issues.
3. `node tools/audit-browser.mjs <dir>` → 0 failing page/viewport combos.
4. `node tools/audit-interactions.mjs` → 0 failing pages.
5. `file://` spot check: open `index.html` and one chapter directly from disk.
6. Update the version table in `about.html` and bump the status line in both READMEs.
7. Commit (English message), push, confirm CI passes.
