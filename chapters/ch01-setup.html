1. RStudio 的四个面板，两条工作区

打开 RStudio，默认看到四个面板：脚本编辑器（左上）写会被保存的代码；控制台（左下）即时执行、适合试探；Environment/History（右上）看当前有哪些对象；Files/Plots/Help（右下）管文件、图和文档。

关键习惯只有一条：凡是想留到明天的代码，都写进脚本。控制台里的内容一关就没；脚本按 Ctrl+Enter（macOS：Cmd+Enter）逐行送进控制台执行。

控制台与脚本两条工作区对比

只在控制台里敲

# 关掉 RStudio 就全部消失
# 三周后没人（包括你）知道
# 当时那行正确的代码是什么

写进脚本，按编号运行

# 00_setup.R → 01_import.R → 02_clean.R
# 每一步可重跑、可审阅、可交给下一个人

2. 对象与赋值：给测量值起名字

R 用 <- 把值存进对象（object）。对象名用小写字母加下划线（snake_case），名字要说明内容而不是类型。

示例 1：创建对象并做一次计算

<- 赋值科研必会
n_mice <- 60
altitude_low_m <- 3200
n_mice * 2
R console
[1] 120

逐行解释

  • 第 1–2 行：创建两个对象；赋值后控制台没有输出——赋值是「存」，不是「说」。
  • 第 3 行：直接写对象名或表达式，结果自动打印，前面的 [1] 是行首序号。

两种赋值号

-> 是反向赋值（60 -> n_mice），效果相同但很少用；= 在函数参数里有别的含义（mean(x, na.rm = TRUE)），教学代码统一用 <-。

常见错误

对象名拼写即换对象：n_mice 和 N_mice 是两个东西。R 对大小写敏感。

示例 2：自动打印与显式打印

print()脚本 vs 控制台
mean_mass_g <- 172.4
mean_mass_g
print(mean_mass_g)
R console
[1] 172.4
[1] 172.4

逐行解释

  • 第 1 行：赋值，无输出。
  • 第 2 行：在控制台/脚本顶层，单独写对象名会自动打印。
  • 第 3 行：print() 显式打印；在函数体或 for 循环里自动打印会失效，此时必须用它。

3. 项目与路径：为什么禁止 setwd

把所有文件放进一个 RStudio Project（File → New Project），项目根目录就是一切路径的起点。绝对路径 setwd("C:/Users/你/Desktop/…") 只在你的电脑上成立；换一台机器、换一个目录，脚本当场断掉。教学代码统一用 here::here()：它从项目根目录出发找文件，与你在哪个目录运行无关。

示例 3：here() 从项目根出发

here科研必会
basename(here::here())
basename(here::here("assets", "data", "pika_physiology.csv"))
R console
[1] "bioR"
[1] "pika_physiology.csv"

逐行解释

  • 第 1 行：here::here() 返回项目根目录（这里用 basename() 只显示最后一级名字，避免暴露每个人的安装路径）。
  • 第 2 行：给 here() 传子目录和文件名，拼出根目录之下的路径——在任何电脑上结果都一样。

常见错误

setwd() 之后脚本「能在你机器上跑」是假象；换目录、换人立即失效。评审与合作都以相对路径为准。

5. 求助与版本记录

查函数用法用 ?mean（打开 Help 面板）；看某个参数长什么样用 args()。每次分析都要记录版本：Methods 里写 R 版本，README 里写包版本——审稿人和三个月后的你都靠它重跑。

示例 5：记录 R 与包版本

sessionInfo可复现
R.version.string
packageVersion("readr")
R console
[1] "R version 4.5.2 (2025-10-31 ucrt)"
[1] '2.2.0'

逐行解释

  • 第 1 行：完整的 R 版本串（含构建日期），直接可写进 Methods。
  • 第 2 行：单个包的版本；把所有包锁进一个文件是第 14 章 renv 的任务，现在先养成记录习惯。

示例 6：用 args() 快速看函数签名

逐行解释

  • 第 1 行：mean 需要 x，其余交给 ...；要知道 na.rm 这类参数，看 ?mean 的 Usage 一节。

科研任务：搭好 pika-hypoxia 项目

在本地新建一个 RStudio Project，然后按下面的步骤把骨架立起来。完成后你将得到本章的三份交付物。

  1. 建项目：File → New Project → New Directory，命名 pika-hypoxia；在项目里建 data-raw/ data/ R/ figures/ reports/ 五个目录。
  2. 放数据：把 pika_physiology.csv 复制进 data-raw/，文件设为只读；在 README 里写一行「原始数据，禁止修改」。
  3. 写 00_setup.R：载入本章用到的包、用 here::here() 定义数据路径、复制原始数据到 data/。
  4. 记录版本：运行 sessionInfo()，把输出保存为 sessionInfo.txt；README 里写清 R 版本和运行顺序。

检查点

  • 关掉 RStudio，重新打开项目，source("00_setup.R") 一键跑通。
  • 全项目搜索不到 setwd 和任何盘符路径。
  • README 能让同门在 10 分钟内跑起你的项目。

常见错误

Error: 'assets/data/does_not_exist.csv' does not exist in current working directory ('C:/…/pika-hypoxia')…

病因：文件名拼错，或文件不在 here::here() 指的位置；报错末尾会告诉你当前工作目录。

修复：用 list.files(here::here("assets/data")) 看真实文件名，逐字符核对。

预防：文件名只用小写、连字符和下划线；路径一律从 here::here() 拼出。

Error in library(notapackage9x) : there is no package called 'notapackage9x'

病因：包没安装（library() 只挂载），或者名字拼错——报错里的引号里就是它找不到的名字。

修复：install.packages("真实包名")，装一次即可，之后每次会话只需 library()。

预防：README 里列出全部依赖及版本。

Error in ggplot() : could not find function "ggplot"

病因：函数属于某个包，而那个包没挂载——函数存在，但当前会话看不见它。

修复：library(ggplot2) 之后再用；或写全名 ggplot2::ggplot()。

预防：把 library() 集中写在 00_setup.R 的开头。

更多同类报错见 R 代码急救室。

先固定分析环境，再谈结果：R 版本、包版本、文件路径三者中任何一个不确定，结果就不可信。版本记录不是行政负担，而是 Methods 的一部分。

原始数据只读是可复现的第一道防线：所有清洗都写成脚本，从 data-raw/ 生成 data/。手动在 Excel 里改一个值，整条证据链就断了。

Analyses were conducted in R version 4.5.2; all package versions are recorded in the project repository, and raw data files were kept read-only.

中文：分析在 R 4.5.2 下完成；全部包版本记录于项目仓库，原始数据保持只读。

小结

可复现项目 = 固定的目录 + 只读的原始数据 + 按编号的脚本 + 记录在案的版本。控制台用来想，脚本用来留。
