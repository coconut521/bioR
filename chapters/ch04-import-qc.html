导入、导出与数据质量：从仪器到 R

酶标仪 CSV 有注释行，实验记录在 Excel，样本表是 CSV——三路数据必须无损进 R，并且先 QC 再分析。

本章科研问题：酶标仪 CSV、Excel 记录和样本表，怎样无损地进 R 并对得上？

105 MIN前置 ch03数据 plate_reader · notebook · metadata_raw交付 02_import_qc.R · qc_report.csv

学习目标

  • 识别仪器导出的注释行，用 skip 跳过并验证维度。
  • 读多 sheet 的 Excel：excel_sheets() 先侦察，再按名字读。
  • 重命名混乱列名，避免空格和特殊字符进 R。
  • 写一个四项 QC：行数、ID 唯一、缺失计数、范围检查。
  • 把 QC 结果导出为 qc_report.csv——它能直接进论文补充材料。
  • 记住规则：QC 报告不是可选附件，是分析的前置条件。

前置：第 3 章；数据：plate_reader_raw.csv、pika_lab_notebook.xlsx、pika_physiology.csv；交付：见封面。

96 孔板的原始导出文件前三行是仪器注释（日期、模式、警告），96 行读数跟在后面；实验记录本是一个两个 sheet 的 Excel；生理样本表是干净 CSV。导师的要求只有一句：「三份东西进 R 以后，行数、列名、缺失都要能对上账——把对账过程给我留档。」

1. 别信仪器：先看裸导入会发生什么

直接 read_csv() 仪器导出，注释行会被当成表头和数据——列数变成 1，第 99「行」其实是真表头。R 甚至发了警告提醒你解析有问题。

示例 1：裸导入仪器 CSV（反面示范）

反面示范read_csv
library(readr)
plate_raw <- read_csv(here::here("assets/data/plate_reader_raw.csv"),
                      show_col_types = FALSE)
ncol(plate_raw)
nrow(plate_raw)
names(plate_raw)[1]
R console
Warning message: One or more parsing issues, call `problems()` on your data frame for details,
e.g.:
  dat <- vroom(...)
  problems(dat)
[1] 1
[1] 99
[1] "# Plate reader export - BioSim xMark (simulated teaching data)"

逐行解释

  • 第 3 行：没加 skip——readr 把第一行注释当成了表头。
  • 输出：1 列、99 行、列名是整句注释。96 个真实读数全被挤进了一个字符列。
  • 警告：readr 明确说「解析有问题，调用 problems() 看细节」——警告不是装饰。

常见错误

「能跑就行」：裸导入的数据没有报错，只是错的。维度对不上（1 列 ≠ 4 列）就是 QC 红旗。

2. skip 跳注释，rename 正列名

示例 2：skip = 3 + 重命名

科研必会rename
library(readr); library(dplyr)
plate <- read_csv(here::here("assets/data/plate_reader_raw.csv"),
                  skip = 3, show_col_types = FALSE) |>
  rename(well_id = well, od600 = od600, temp_c = temperature_c)
ncol(plate)
nrow(plate)
names(plate)
R console
[1] 4
[1] 96
[1] "well_id" "od600"   "temp_c"  "cycle"

逐行解释

  • 第 3 行：skip = 3 跳过三行注释，真实表头顶上来了。
  • 第 4–5 行：管道重命名。well 改成 well_id 是为了防止和将来 join 的键撞名；列名保持小写下划线。
  • 输出：4 列 × 96 行——与仪器设置一致，QC 过了第一关。

janitor 对照

janitor::clean_names() 一行把全部列名转成 snake_case，适合列很多的情况；本章列少，显式 rename() 意图更清楚。

2'. 补充：problems() 与 col_types

readr 每次解析都会留下「解析问题清单」。用 problems() 查看；列类型可用 col_types = cols(...) 显式指定，避免猜测错误。第 7 章会遇到 join 类型的坑，第 18 章会遇到 counts 必须是整数的坑——都始于导入这一步。

4. QC：四项检查，一次对账

pika <- read_csv(here::here("assets/data/pika_physiology.csv"),

sum(is.na(pika$hemoglobin_g_l))
sum(duplicated(pika$id))

R console
[1] 2
[1] 0

逐行解释

  • 第 4 行：缺失计数 = 2，与数据字典「NA = 溶血」对账。
  • 第 5 行：ID 重复 = 0（第 3 章的检查，进 QC 报告留档）。
  • 第 6 行：体重越界 = 0——注意 ch02 见过的「先想缺失」：范围比较带 na.rm = TRUE。

5. 把 QC 变成一份可交档的报告

示例 5：qc_report 表——期望值 vs 实查值

科研必会tibble
library(readr); library(dplyr); library(writexl)
pika <- read_csv(here::here("assets/data/pika_physiology.csv"),
                 show_col_types = FALSE)
qc <- tibble(
  check = c("rows", "unique_id", "hb_missing", "mass_out_of_range"),
  expected = c("60", "60", "2", "0"),
  found = c(as.character(nrow(pika)),
            as.character(n_distinct(pika$id)),
            as.character(sum(is.na(pika$hemoglobin_g_l))),
            as.character(sum(pika$body_mass_g < 110 |
                               pika$body_mass_g > 240, na.rm = TRUE))))
qc
R console
# A tibble: 4 × 3
  check             expected found
  <chr>             <chr>    <chr>
1 rows              60       60   
2 unique_id         60       60   
3 hb_missing        2        2    
4 mass_out_of_range 0        0

逐行解释

  • 第 4–9 行：tibble() 建 QC 表：expected 来自数据字典（设计决定），found 来自实查。
  • 对账：expected == found 逐行成立，QC 通过；任何一行不一致，先停下找原因，不许继续分析。
  • 第 1 行：挂了 writexl——正式任务里 write_csv(qc, here::here("data/qc_report.csv")) 把报告落盘。

QC 报告是「分析合法性的证据链」：expected 由设计写出（60 只、3 组、字典缺失数），found 由代码实查。两者都进版本库，补充材料直接引用。

科研任务：三路导入 + qc_report.csv

把本章示例串成 02_import_qc.R。完成后你将得到 qc_report.csv。

  1. 仪器 CSV：skip = 3 导入，重命名列名，验证 96 × 4。
  2. Excel：读 incidents sheet，确认 5 条异常与数据缺失对应。
  3. QC 四项：对 pika 跑行数/ID/缺失/范围，写成 expected-vs-found 表。
  4. 落盘：write_csv(qc, here::here("data/qc_report.csv"))；在脚本顶部注释写明检查日期与依据的字典版本。

检查点

  • qc_report.csv 每行 expected == found。
  • 脚本无 setwd、无裸导入（注释行已跳过）。
  • 重跑输出一致（确定性）。

常见错误

Error: 'assets/data/plate_reader_raw.csv' does not exist in current working directory ('C:/…/reports')…

病因：当前工作目录不是项目根（你在 reports/ 里跑了脚本），或文件名拼错。

修复：here::here() 拼路径 + list.files() 核对。

预防：脚本永远从项目根或用 here 引用；报错末尾的 working directory 信息要读。

Warning message: One or more parsing issues, call `problems()` …

病因：readr 猜列类型时遇到冲突行（注释、缺分隔符）。

修复：problems(plate_raw) 逐条看；该 skip 的 skip、该指定 col_types 的指定。

预防：导入后立刻 dim() + names() 与源文件对照。

Error: Can't find sheet 'Incidents' …

病因：sheet 名大小写或拼写与 excel_sheets() 列出的不一致。

修复：照 excel_sheets() 的原文写；按名不按序号。

预防：Excel 交付时约定 sheet 命名规范。

更多同类报错见 R 代码急救室。

先 QC 再分析：QC 结果是排除规则和有效 n 的依据，要进补充材料。数据字典里 missing = 2 不是「知道就好」——它是 expected 列的来源。

类型转换的丢失是静默的：超出检测限的「<0.05」、混进单位的「3.2 mg」都会让整列变字符，as.numeric 一转变 NA。转换前后必须 sum(is.na()) 对账（第 2 章的规则在导入场景同样成立）。

Raw instrument exports were imported programmatically (readr 2.2.0) with header comments skipped; data quality was verified against a pre-registered checklist covering row count, identifier uniqueness, missingness, and biologically plausible ranges.

中文：仪器原始导出以程序导入（readr 2.2.0）并跳过表头注释；按预登记清单核查行数、标识符唯一性、缺失与生物学合理范围。

小结

导入三件套：skip 跳注释、rename 正列名、dim/names 对维度。QC 四件套：行数、ID、缺失、范围——expected 来自字典，found 来自实查，对账报告落盘。
