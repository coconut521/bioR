函数、控制流与模拟：把重复分析变成工具

同一段 QC 写第三遍的时候，就该把它写成函数了——然后让模拟替你回答「n 要多大」。

本章科研问题：三个批次各一个 CSV，怎样用同一套 QC 一次跑完？为什么 n 越大均值越稳？

90–120 MIN前置 ch04数据 3 批次 CSV · pika_physiology.csv交付 R/qc_functions.R · fig_sampling_error.svg

学习目标

  • 用 function() 写出带参数、有返回值的 qc_summary(df)，并用 stopifnot() 校验输入。
  • 读写 if/else 与 for，知道循环要先分配再填空位。
  • 用 purrr::map_dfr() 把同一函数应用到多个文件并拼成一张表。
  • 用 tryCatch() 捕获错误，让一个坏文件不中断整批处理。
  • 用 replicate() + set.seed() 模拟 1000 次抽样，画标准误随 n 的变化。
  • 说清「标准误」与「标准差」的区别。

前置：第 4 章；数据：三个批次 CSV（本章现场生成）、pika_physiology.csv；交付：R/qc_functions.R、fig_sampling_error.svg。

三个批次的数据分别躺在三个 CSV 里，导师要的却是同一套 QC。复制粘贴三次？改一处就得改三处。这一章把重复分析封装成函数、用 map 批量执行、用 tryCatch 隔离故障——然后借同样的思路做一件事模拟实验：亲手看到 n 变大时均值如何变稳。

1. 函数：把重复的分析变成工具

函数 = 输入（参数）→ 处理 → 输出（返回值）。写函数的头一条纪律是校验输入：stopifnot() 把「调用者拿错了数据」变成一行明确的报错，而不是三行之后莫名其妙的结果。

示例 1：qc_summary(df)——带输入校验的 QC 函数

function · stopifnot科研必会
qc_summary <- function(df) {
  stopifnot(is.data.frame(df), "hemoglobin_g_l" %in% names(df))
  tibble::tibble(
    n_total = nrow(df),
    n_missing = sum(is.na(df$hemoglobin_g_l)),
    mean_hb = round(mean(df$hemoglobin_g_l, na.rm = TRUE), 1)
  )
}
library(readr)
pika <- read_csv(here::here("assets/data/pika_physiology.csv"),
                 show_col_types = FALSE)
qc_summary(pika)
R console
# A tibble: 1 × 3
  n_total n_missing mean_hb
    <int>     <int>   <dbl>
1      60         2    164.

逐行解释

  • 第 1 行：function(df) 定义参数；函数体最后一行的值就是返回值。
  • 第 2 行：stopifnot() 两条校验——是数据框、有血红蛋白列。传错对象立即报错。
  • 第 3–7 行：返回一张一行小表：总行数、缺失数、均值。缺失数与第 4 章 QC 对账（2 个 NA = 溶血）。
  • 第 11 行：对真实数据调用。真实均值 164.3 g/L（n = 58 有效）。

常见错误

函数体里悄悄引用全局变量（比如直接用 pika 而不用参数 df）——换个数据就失效。函数只依赖自己的参数，才能被复用。

2. 控制流：if、for 与陷阱

脚本有了分叉和循环才像程序：if/else 做判断，for 做重复。R 的循环没问题，问题出在两种经典写法上——循环里用 c() 反复增长向量，以及把 T/F 当常量用。

示例 2：for 循环的正确写法与 T/F 陷阱

for · preallocate建模前置
n <- 5
res <- numeric(0)
for (i in 1:n) res <- c(res, sqrt(i))  # 每轮都新建一个更长的向量
res
identical(res, sqrt(1:n))

fast <- numeric(n)
for (i in 1:n) fast[i] <- sqrt(i)      # 先分配、再填空位
identical(res, fast)

T <- 0                                  # T 不是保留字，会被覆盖
if (T) "run" else "skip"
rm(T)
TRUE == 1
R console
[1] 1.000000 1.414214 1.732051 2.000000 2.236068
[1] TRUE
[1] TRUE
[1] "skip"
[1] TRUE

逐行解释

  • 第 3 行：每个元素 append 一次，R 都要复制整个向量再长一格——n 大时是 O(n²) 的隐形减速。n = 5 察觉不到，n = 5 万就很痛。
  • 第 6–7 行：正确写法：numeric(n) 一次分配好 n 个空位，循环里按位置填。
  • 第 10–12 行：T 只是个普通变量！T <- 0 之后 if (T) 走了 else 分支。TRUE 是保留字，永远覆盖不了。

常见错误

set.seed() 放进循环体里：每一轮都重置同一颗种子，模拟出的「1000 次」其实是同一次抽样复制 1000 遍。种子放循环外，只放一次。

3. 批量处理：map 把函数应用到每个文件

有了函数，三个文件就是三次调用。purrr::map_dfr() 逐个执行、把每个返回的小表按行拼接成一张总表——这就是「函数 × 批量」的组合拳。

示例 3：map_dfr 批量 QC 三个批次

map_dfr · map2科研必会
library(readr); library(purrr); library(dplyr)
make_batch_file <- function(batch, n, seed) {
  set.seed(seed)  # 每个文件一次种子：种子跟着数据走，不放循环外层
  f <- tempfile(fileext = ".csv")
  write_csv(data.frame(id = sprintf("%s%02d", batch, 1:n),
                       hemoglobin_g_l = round(rnorm(n, 155, 12), 1)), f)
  f
}
files <- c(make_batch_file("B1", 5, 11), make_batch_file("B2", 5, 22),
           make_batch_file("B3", 5, 33))
qc_batch <- function(batch, path) {
  d <- read_csv(path, show_col_types = FALSE)
  tibble(batch = batch, n = nrow(d),
         mean_hb = round(mean(d$hemoglobin_g_l), 1))
}
map2_dfr(c("B1", "B2", "B3"), files, qc_batch)
R console
# A tibble: 3 × 3
  batch     n mean_hb
  <chr> <int>   <dbl>
1 B1        5    150.
2 B2        5    162.
3 B3        5    151.

逐行解释

  • 第 1–8 行：现场生成三个批次 CSV（示例自包含；真实项目里它们来自仪器）。种子固定，每次重跑数据一致。
  • 第 9–13 行：qc_batch(batch, path) 读一个文件、返回一行小表——和示例 1 的 qc_summary() 同一思路。
  • 第 14 行：map2_dfr(labels, files, qc_batch) 把标签和路径成对传入（map2 两个输入并行迭代），三张小表按行拼成总表。

常见错误

map_dfr(files, qc_batch) 里 qc_batch 又调用了 batch 变量——那个变量并不存在，报 object 'batch' not found。批量函数需要的每一列输入都得来自 map 系列的参数（一个输入用 map，两个用 map2）。

4. 容错：tryCatch 别让一个坏文件毁掉整批

批量处理的命门是一个文件出错、整批中断。仪器崩溃、同事改列名、编码错乱——都会发生。tryCatch() 把「出错」变成一种可以处理的结果：坏了就记一行，其余照跑。

示例 4：tryCatch 让批量 QC 不中断

tryCatch稳健性
library(readr); library(purrr); library(dplyr)
make_batch_file <- function(batch, n, seed) {
  set.seed(seed)
  f <- tempfile(fileext = ".csv")
  write_csv(data.frame(id = sprintf("%s%02d", batch, 1:n),
                       hemoglobin_g_l = round(rnorm(n, 155, 12), 1)), f)
  f
}
files <- c(make_batch_file("B1", 5, 11), make_batch_file("B2", 5, 22),
           make_batch_file("B3", 5, 33))
# 同事把第三个文件改成了体重表：列名对不上了
write_csv(data.frame(id = "B301", weight_g = 44), files[3])
qc_batch <- function(batch, path) {
  tryCatch({
    d <- read_csv(path, show_col_types = FALSE)
    if (!"hemoglobin_g_l" %in% names(d)) stop("missing hemoglobin_g_l column")
    tibble(batch = batch, n = nrow(d),
           mean_hb = round(mean(d$hemoglobin_g_l), 1), note = "ok")
  }, error = function(e) {
    tibble(batch = batch, n = NA, mean_hb = NA, note = conditionMessage(e))
  })
}
map2_dfr(c("B1", "B2", "B3"), files, qc_batch)
R console
# A tibble: 3 × 4
  batch     n mean_hb note                         
  <chr> <int>   <dbl> <chr>                        
1 B1        5    150. ok                           
2 B2        5    162. ok                           
3 B3       NA     NA  missing hemoglobin_g_l column

逐行解释

  • 第 10 行：故意制造一个坏文件（列名被改）——模拟真实世界里的「同事改表」。
  • 第 12–14 行：tryCatch 的「尝试」块：读入后先验证关键列存在，缺列主动 stop()。
  • 第 15–17 行：error 处理器返回同结构的一行（n、mean 填 NA，note 记错误信息）——坏文件不炸整批，而是留下一条记录。

常见错误

error 处理器返回空或返回 NULL——坏文件就从结果里消失了，批量表悄悄少一行。失败必须留下痕迹：NA 行 + note 列，事后才追查得到。

5. 模拟：为什么 n 越大均值越稳

模拟是统计的显微镜。我们造一个已知答案的总体（μ = 155、σ = 12 g/L 的正态分布），反复抽样、算均值，看均值的波动如何随 n 变化。replicate() = 「把一个表达式跑 N 遍并收集结果」，set.seed() 保证下次重跑结果一模一样。

示例 5：replicate 模拟 1000 次抽样

replicate · set.seed理解统计
set.seed(20261027)
n_draw <- 10
sim <- replicate(1000, {
  s <- rnorm(n_draw, 155, 12)
  c(mean = mean(s), sd = sd(s))
})
sim_m <- t(sim)
means <- sim_m[, "mean"]
c(mean_of_means = round(mean(means), 1),
  se_of_means   = round(sd(means), 1))
round(12 / sqrt(n_draw), 2)
R console
mean_of_means   se_of_means 
        155.2           3.8 
[1] 3.79

逐行解释

  • 第 1 行：固定随机种子——重跑脚本，模拟结果一字不差（可复现的第一原则）。
  • 第 3–6 行：每次抽 n = 10 个个体、记下这组的均值与标准差；replicate 重复 1000 次，得 1000 个均值。
  • 第 9–11 行：均值们的均值 ≈ 155（还原总体 μ）；均值们的标准差 ≈ 3.8——这就是标准误。
  • 第 12 行：理论标准误 σ/√n = 12/√10 = 3.79，和模拟几乎重合——理论不是天上掉下来的。

常见错误

把「均值的标准差」（3.8）当成「单个观测的标准差」（12）写进论文。它们差 √n 倍：n = 10 时，标准误只是标准差的 1/√10。

检查点

  • 把 qc_summary() 喂一个错误对象（如 qc_summary(1:10)），必须立刻报错——校验在工作。
  • 种子只出现一次；删掉 set.seed() 重跑，均值会变——这解释了为什么脚本必须固定种子。
  • QC 总表行数 = 文件数；tryCatch 版本里坏文件有 NA 行和 note。

常见错误

Error in qc_summary(plate_raw) : "hemoglobin_g_l" %in% names(df) is not TRUE

病因：给 qc_summary() 喂错了表——酶标仪数据没有血红蛋白列。这是 stopifnot() 在替你把关。

修复：核对输入 names(df)；确认真该处理这张表再调用。

预防：每个函数开头校验输入；宁可第一行报错，不要第五行出错结果。

Error: object 'n_draw' not found

病因：函数体里用了全局变量 n_draw——在自己电脑能跑，换环境（source 到新会话、Rscript）就崩。

修复：把 n_draw 变成函数参数 function(df, n_draw)，调用时显式传入。

预防：函数只依赖参数；调试时用 codetools::findGlobals(f) 查隐性依赖。

Error: C stack usage 7971912 is too close to the limit

病因：递归/循环写成没有终止条件的死循环，一层层压栈直到爆掉。

修复：检查循环变量是否更新、递归是否有 base case；while 循环补上退出条件。

预防：能数出次数的重复用 for/map；while 只在「不知道要循环几次」时用。

更多同类报错见 R 代码急救室。

标准误不是标准差。标准差（σ ≈ 12）描述个体之间的真实差异，它不随 n 变；标准误（σ/√n）描述「样本均值这个估计量」的不确定性，n 越大越稳。模拟回答的是「估计有多准」，不能替代实验设计——n 的最终选择要靠功效分析（第 30 号速查表与第 12 章）。

模拟结果因种子而异：set.seed(20261027) 之后，本页每个数字都可逐位复现。把种子写进脚本注释，审稿人问起时一句话答完。

To quantify sampling variability, 1,000 random samples of size n were drawn from a normal population (μ = 155, σ = 12 g/L) using fixed seed 20261027; the standard error of the mean was estimated as the standard deviation of sample means and compared with the theoretical value σ/√n.

中文：为量化抽样波动，从已知正态总体（μ = 155、σ = 12 g/L）以固定种子 20261027 抽取 1000 个容量为 n 的样本；以样本均值的标准差估计标准误，并与理论值 σ/√n 对照。

小结

重复三次以上的分析写成函数（校验输入、只依赖参数）；批量用 map/map2_dfr，坏文件用 tryCatch 留痕。模拟 1000 次抽样直观展示 σ/√n：n 变大变稳的是标准误，不是标准差。
