数据整形：用 dplyr 把实验表变成答案

五个动词、一条管道：从 60 行原始表，走到 6 行按海拔×性别汇总的 Table 1。

本章科研问题：哪个海拔组、哪种性别的血红蛋白更高？高海拔的差异有多大？

学习目标

  • 用 filter()/select() 写出排除规则并生成排除日志。
  • 用 mutate() + case_when() 派生条件变量，避开顺序陷阱。

  • 分清 n()（数行）与 sum(!is.na())（数有效值）。
  • 端到端生成 table1_group.csv，并知道 base R 的 aggregate() 对照。
  • 说清排除规则为什么必须在看 p 值之前定下。

前置：第 5 章；数据：pika_physiology.csv；交付：table1_group.csv、exclusions.csv。

血红蛋白随海拔升高而升高——这是本课题的核心假设。回答它不需要任何花哨统计：先排除不合格的行（规则先于结果），再按海拔×性别分组汇总。dplyr 把这两件事压缩成一条可读的管道；这一章同时立下一条科研纪律：排除规则一旦写下，就不许再改。

1. 排除规则：在看任何统计之前

排除规则要满足三条：写在数据字典里（标准客观）、记进日志（谁被排、为什么）、先于结果（不能看了一眼 p 值再把某组删掉）。本章规则：血红蛋白缺失（溶血）或体重超出 110–240 g。

示例 1：filter 排除 + 保留被排除的行

filter · select科研必会
library(readr); library(dplyr)
pika <- read_csv(here::here("assets/data/pika_physiology.csv"),
                 show_col_types = FALSE)
pika |>
  filter(!is.na(hemoglobin_g_l), body_mass_g >= 110, body_mass_g <= 240) |>
  nrow()
pika |>
  filter(is.na(hemoglobin_g_l) | body_mass_g < 110 | body_mass_g > 240) |>
  select(id, body_mass_g, hemoglobin_g_l)
R console
[1] 58
# A tibble: 2 × 3
  id    body_mass_g hemoglobin_g_l
  <chr>       <dbl>          <dbl>
1 P017         215.             NA
2 P042         173.             NA

逐行解释

  • 第 4–6 行：排除后的行数 = 58。filter 里多个条件用逗号连接 = 「同时满足」（AND）。
  • 第 7–10 行：同一规则的反面——被排除的 2 行（P017、P042，血红蛋白 NA = 溶血）。体重规则没有排除任何行，这本身也是要记录的事实。

常见错误

filter(hemoglobin_g_l > 100)：NA 参与任何比较都是 NA，NA 行会被悄悄丢弃。想显式处理缺失，先写 !is.na()，或用 is.na() 单独分一支。

2. mutate 与 case_when：派生条件变量

case_when() 按从上到下的顺序取第一个命中的分支——相当于 if / else if / else。顺序写错不会报错，只会悄悄把分类弄错，这是本章最阴的陷阱。

示例 2：体重分级与顺序陷阱

mutate · case_when科研必会
library(readr); library(dplyr)
pika <- read_csv(here::here("assets/data/pika_physiology.csv"),
                 show_col_types = FALSE)
pika <- pika |>
  mutate(mass_class = case_when(
    body_mass_g < 150 ~ "light",
    body_mass_g < 200 ~ "normal",
    body_mass_g <= 240 ~ "heavy"
  ))
count(pika, mass_class)
# 顺序错了：宽条件放前面，heavy 把 normal 也吞掉
pika |>
  mutate(mass_bad = case_when(
    body_mass_g <= 240 ~ "heavy",
    body_mass_g < 200 ~ "normal"
  )) |>
  count(mass_bad)
R console
# A tibble: 3 × 2
  mass_class     n
  <chr>      <int>
1 heavy          2
2 light          3
3 normal        55
# A tibble: 1 × 2
  mass_bad     n
  <chr>    <int>
1 heavy       60

逐行解释

  • 第 5–8 行：从窄到宽的区间按升序排列——每支条件只对「前面都没接住」的行生效，235 g 的个体走到第三支才被接住。
  • 第 9 行：light 3 / normal 55 / heavy 2（P023 = 232、P011 = 205 两只大个体进 heavy）。
  • 第 11–17 行：把宽条件 <= 240 放前面后，几乎所有人都被吞进 heavy（60 只）——case_when() 不报错，你得靠 count() 才能发现。

常见错误

分支条件有漏洞（比如 > 240 没人接）→ 结果变 NA，而且是静默的。收尾加一行 TRUE ~ NA 把漏洞显式化，再决定要不要排除。

3. group_by + summarise：分组汇总

统计的核心动作：group_by() 划组，summarise() 把每组压成一行。这一对组合生成 Table 1 的全部数字——n、均值±SD、中位数(IQR)。

示例 3：按海拔组汇总血红蛋白

group_by · summarise科研必会
library(readr); library(dplyr)
pika <- read_csv(here::here("assets/data/pika_physiology.csv"),
                 show_col_types = FALSE)
pika |>
  group_by(altitude_group) |>
  summarise(
    n = n(),
    n_valid = sum(!is.na(hemoglobin_g_l)),
    hb_mean = round(mean(hemoglobin_g_l, na.rm = TRUE), 1),
    hb_sd = round(sd(hemoglobin_g_l, na.rm = TRUE), 1),
    .groups = "drop"
  )
R console
# A tibble: 3 × 5
  altitude_group     n n_valid hb_mean hb_sd
  <chr>          <int>   <int>   <dbl> <dbl>
1 high              20      19    178.  13.7
2 low               20      19    149    8  
3 mid               20      20    165.   9.3

逐行解释

  • 第 6 行：n() 数每组的行数；第 7 行 sum(!is.na()) 数有效值——未排除缺失时两者不等（下一节展开）。
  • 第 8–9 行：na.rm = TRUE 剔除 NA 再算；两个函数都写了 na.rm——少了它，任何含 NA 的组结果是 NA。
  • 第 10 行：.groups = "drop" 显式取消分组——不留「隐式分组」状态给下一段代码。
  • 结果：high 178.5 vs low 149.0 g/L——近 30 g/L 的海拔差，核心假设的方向得到支持。

常见错误

省略 .groups：summarise 默认按倒数第一个分组变量保留分组。后续 mutate() 会在组内悄悄执行，结果看似正常实则错。养成习惯：汇总完立刻 .groups = "drop" 或 ungroup()。

4. n() 与 sum(!is.na())：两种计数

n() 数行——数据里的每个位置都算，包括 NA；sum(!is.na()) 数有效观测。论文 Table 1 里的 n 必须是后者。什么时候两者相等？排除缺失之后。

示例 4：排除前后的两种 n

n() vs sum(!is.na())统计判断
library(readr); library(dplyr)
pika <- read_csv(here::here("assets/data/pika_physiology.csv"),
                 show_col_types = FALSE)
# 未排除缺失：n() 把 NA 也数进去
pika |>
  group_by(altitude_group) |>
  summarise(n_all = n(), n_valid = sum(!is.na(hemoglobin_g_l)))
# 排除缺失之后两者相等
pika |>
  filter(!is.na(hemoglobin_g_l)) |>
  group_by(altitude_group) |>
  summarise(n_all = n(), n_valid = sum(!is.na(hemoglobin_g_l)))
R console

逐行解释

  • 第一张表：high 与 low 各 n_all = 20 但 n_valid = 19——每个海拔组各有 1 个溶血 NA。报告 n 时写错列，高海拔的统计功效就虚报一格。
  • 第二张表：排除后 n_all == n_valid——这是「有效 n 与行数一致」的对账检查，应该写进脚本。

5. 端到端 Table 1：排除日志 + 分组汇总

把前面的零件装成一条完整管线：排除 → 记日志 → 分组 → 汇总 → 导出 CSV。这就是 06_table1.R 的骨架，也是你以后每个数据集第一天该写的脚本。

示例 5：Table 1（海拔 × 性别）与排除日志

端到端科研必会
library(readr); library(dplyr)
pika <- read_csv(here::here("assets/data/pika_physiology.csv"),
                 show_col_types = FALSE)
dir.create(here::here("data"), showWarnings = FALSE)  # 交付物目录（第 1 章的项目结构）
excluded <- pika |>
  filter(is.na(hemoglobin_g_l) | body_mass_g < 110 | body_mass_g > 240) |>
  transmute(id, rule = case_when(
    is.na(hemoglobin_g_l) ~ "hemoglobin missing",
    TRUE ~ "mass out of range"))
write_csv(excluded, here::here("data/exclusions.csv"))
analysis <- pika |>
  filter(!is.na(hemoglobin_g_l), body_mass_g >= 110, body_mass_g <= 240)
table1 <- analysis |>
  group_by(altitude_group, sex) |>
  summarise(
    n = n(),
    mass_mean_sd = sprintf("%.1f ± %.1f", mean(body_mass_g), sd(body_mass_g)),
    mass_median_iqr = sprintf("%.1f (%.1f–%.1f)",
      median(body_mass_g), quantile(body_mass_g, .25), quantile(body_mass_g, .75)),
    hb_mean_sd = sprintf("%.1f ± %.1f",
      mean(hemoglobin_g_l), sd(hemoglobin_g_l)),
    .groups = "drop"
  )
write_csv(table1, here::here("data/table1_group.csv"))
table1
# base R 对照：aggregate() 一次算两列
aggregate(cbind(body_mass_g, hemoglobin_g_l) ~ altitude_group + sex,
          data = analysis, function(x) round(c(mean = mean(x), sd = sd(x)), 1))

逐行解释

  • 第 5–9 行：排除日志——被排除的行 + case_when 标注原因，write_csv 存为 exclusions.csv。
  • 第 13–23 行：按海拔 × 性别（6 组）汇总；sprintf() 把数字排成「均值 ± SD」「中位数 (Q1–Q3)」的期刊格式。
  • 第 24 行：write_csv() 把 Table 1 落盘为 table1_group.csv——与排除日志同目录，两份交付物齐了。
  • 第 26–28 行：base R 对照——aggregate() 公式接口一次算两列的均值与 SD，验证 dplyr 结果。

常见错误

summarise(mean = body_mass_g) 想返回整列——报错 must return a single value。summarise 的每个参数必须把一组压成一个值；要保留整列用 mutate()。

常见错误

Error in `summarise()`: ℹ In argument: `hb_mean = mean(...)`. Caused by error: `hb_mean` must return a single value, not 20.

病因：summarise 里忘了包 mean()/n()，返回了整列向量。

修复：每个参数都得把一组压成一个值——mean、median、quantile、n()…

预防：报错信息里的「not 20」= 组大小；summarise 保留整列请改用 mutate。

Error in `filter()`: ℹ In argument: `body_mass >= 110`. Caused by error: object 'body_mass' not found.

病因：列名拼错（少了 _g）。dplyr 动词里直接写列名，不写 pika$。

修复：names(pika) 核对；RStudio 里 Ctrl+Space 补全。

预防：全站统一 snake_case（第 4 章导入时就重命名好）。

Error in `group_by()`: Must group by variables found in `.data`. Column `Altitude_group` not found.

病因：大小写写错。R 列名区分大小写，altitude_group ≠ Altitude_group。

修复：改回全小写；或导入时 rename() 统一命名。

预防：报错里会列出最接近的候选名，先读报错再动手。

更多同类报错见 R 代码急救室。

排除规则必须在看 p 值之前定下——否则它就是一台「把结果磨好看」的机器。Table 1 要写清每个变量用的是均值±SD（近似正态）还是中位数(IQR)（偏态或有离群值），并把选择依据写进表注。本章的排除日志是这两个纪律的物理载体。

table1_group.csv 与 exclusions.csv 都由 06_table1.R 从原始数据再生成——修改任何一步都发生在脚本里，重跑即生效。

Individuals with missing hemoglobin (hemolysis, n = 2) or body mass outside the pre-specified range 110–240 g were excluded before any inferential test; group-wise summaries are reported as mean ± SD with median (IQR) for body mass, by altitude group and sex (Table 1).

中文：血红蛋白缺失（溶血，n = 2）或体重超出预定范围 110–240 g 的个体在任何推断检验前被排除；按海拔组与性别汇总，体重同时报告均值±SD 与中位数(IQR)（表 1）。

小结

排除规则先于结果并留日志；case_when 从上到下取分支、顺序即语义；group_by+summarise 一组一行，n() 数行、sum(!is.na()) 数有效观测；.groups="drop" 不留隐式分组。端到端产出 table1_group.csv 与 exclusions.csv。
