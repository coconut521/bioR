宽长转换与多表连接：当表达矩阵遇上样本表

2000 个基因 × 12 个样本，加上一张 12 行的样本表——连接的键对不上，样本就悄悄消失。

本章科研问题：counts 列名 C1…H6 与样本表里的「H-5」「 C3」对不上时，样本是怎么丢的？

90–120 MIN前置 ch06数据 pika_rnaseq_counts.csv · metadata_raw交付 expr_long.csv · join_qc.csv

学习目标

  • 用 pivot_longer() 把 2000 × 12 的宽矩阵转成 24 000 × 4 的长表。
  • 用 anti_join() 在连接之前找出不匹配的样本 ID。
  • 用 str_trim() / str_replace() 清洗连接键（空格、连字符）。
  • 用 left_join() 连接并用行数对账证明没有丢样本（12/12）。
  • 认出多对多连接的警告，并知道它会让行数膨胀。
  • 导出 expr_long.csv 与 join_qc.csv。

前置：第 6 章；数据：pika_rnaseq_counts.csv、pika_rnaseq_metadata_raw.csv；交付：expr_long.csv、join_qc.csv。

RNA-seq 分析的标准流程是：表达矩阵（宽表）→ 长表 → 连接样本信息 → 分组比较。这一步丢一个样本，n 就从 6 变成 5，后面的差异分析全跟着错。连接不是家务事，是分析本身——所以这一章的主角是 anti_join()：先看丢没丢，再决定连不连。

1. 宽表与长表：计数矩阵的形状问题

表达矩阵天然是宽表：列名是样本，行是基因。ggplot 与分组统计要的是长表：一行一次「基因 × 样本」观测。pivot_longer() 把样本列「收」进两列——sample_id 与 count。

示例 1：2000 × 12 矩阵转 24 000 行长表

pivot_longer科研必会
library(readr); library(dplyr); library(tidyr)
counts <- read_csv(here::here("assets/data/pika_rnaseq_counts.csv"),
                   show_col_types = FALSE)
meta <- read_csv(here::here("assets/data/pika_rnaseq_metadata_raw.csv"),
                 show_col_types = FALSE)
dim(counts)
dim(meta)
expr_long <- counts |>
  pivot_longer(cols = -c(gene_id, gene_name),
               names_to = "sample_id", values_to = "count")
dim(expr_long)
head(expr_long, 3)

逐行解释

  • 第 5–6 行：矩阵 2000 × 14（gene_id、gene_name + 12 个样本列）；样本表 12 × 5。
  • 第 7–9 行：cols = -c(gene_id, gene_name) 收掉其余 12 列——2000 × 12 = 24 000 行，每行一个「基因 × 样本」的 count。

常见错误

cols = -gene_id 只排除一列 → gene_name 也被当成样本值「收」进 count，得到一个全是字符的假 count 列。收列前先想清楚：哪些列是标识，哪些列才是样本。

2. 连接之前先对抗：anti_join 找不匹配

anti_join(x, y) 返回「在 x 里但不在 y 里」的行——它是连接 QC 的探照灯。先跑它，才知道直接 join 会丢什么。这里有一个隐蔽的坑：readr 默认会替你把空格修掉（trim_ws = TRUE），所以要用 trim_ws = FALSE 才能看到真实的脏数据。

示例 2：三个对不上的样本 ID

meta <- read_csv(here::here("assets/data/pika_rnaseq_metadata_raw.csv"),
                 show_col_types = FALSE, trim_ws = FALSE)
anti_join(meta, tibble(sample_id = names(counts)[-(1:2)]), by = "sample_id")

常见错误

直接 left_join() 然后看结果「好像也对」——那 3 个样本的 group 变成了 NA，后面的分组统计悄悄少 3 个样本。连接前不 anti_join，等于蒙眼过马路。

3. 清洗连接键：trim 与替换

找到问题就修键，而不是修 join 的参数：str_trim() 去首尾空格，str_replace("^H-", "H") 把 H-5 规范成 H5。清洗完再 anti_join() 一次——必须为空。

示例 3：清洗后 12/12 全部匹配

str_trim · str_replace科研必会
library(readr); library(dplyr); library(stringr)
counts <- read_csv(here::here("assets/data/pika_rnaseq_counts.csv"),
                   show_col_types = FALSE)
meta <- read_csv(here::here("assets/data/pika_rnaseq_metadata_raw.csv"),
                 show_col_types = FALSE, trim_ws = FALSE)
meta_clean <- meta |>
  mutate(sample_id = sample_id |>
           str_trim() |>
           str_replace("^H-", "H"))
anti_join(meta_clean, tibble(sample_id = names(counts)[-(1:2)]), by = "sample_id")
sum(meta_clean$sample_id %in% names(counts))

逐行解释

  • 第 7–9 行：管道式清洗：先 trim，再规范连字符。两条规则都写成代码，下批数据照跑。
  • 第 10 行：清洗后再 anti_join → 0 行（空 tibble）。这是「键已对齐」的机械证明。
  • 第 11 行：12/12 命中——所有样本都能拿到分组信息，可以进入 join。

常见错误

在 Excel 里手动改 12 个 ID——这次对了，下批 200 个样本还是错。清洗规则进脚本，并写进方法学（连字符不一致是常见的手工录入问题）。

4. join 与行数对账：不丢样本

连接本身只有一行代码。真正的功夫在连接之后的三条对账：长表行数不变、分组信息无 NA、反方向 anti_join 为空。左边 24 000 行，连接后还是 24 000 行——这才叫没丢。

示例 4：left_join + 三条对账

left_join科研必会
library(readr); library(dplyr); library(tidyr)
counts <- read_csv(here::here("assets/data/pika_rnaseq_counts.csv"),
                   show_col_types = FALSE)
meta_clean <- read_csv(here::here("assets/data/pika_rnaseq_metadata_clean.csv"),
                       show_col_types = FALSE)
expr_long <- counts |>
  pivot_longer(cols = -c(gene_id, gene_name),
               names_to = "sample_id", values_to = "count")
joined <- expr_long |>
  left_join(meta_clean, by = "sample_id")
dim(expr_long)
dim(joined)
sum(is.na(joined$group))
anti_join(expr_long, meta_clean, by = "sample_id") |> nrow()
R console
[1] 24000     4
[1] 24000     8
[1] 0
[1] 0

逐行解释

  • 第 10–11 行：left_join 按 sample_id 补上 group/batch/sex/library_size——4 列变 8 列。
  • 第 12–13 行：行数对账：24 000 → 24 000。不变 = 没有丢、也没有膨胀。
  • 第 14 行：分组列 0 个 NA——没有任何样本「连上了但没信息」。
  • 第 15 行：反方向 anti_join = 0——矩阵里的每个样本都能在样本表找到。

常见错误

样本表里同一个 ID 出现两次（重复录入）→ 多对多连接，24 000 行可能变 24 001 行，而且静默。dplyr 会警告 many-to-many relationship，但脚本照跑。看到这条警告就停下，先count(sample_id) 查重。

5. 端到端：expr_long.csv 与 join_qc.csv

把清洗、长表、连接、对账装成一条管线；两份交付物：分析用的长表，和一张连接 QC 表。QC 表进补充材料——它是「没丢样本」的书面证据。

示例 5：从原始文件到两份交付物

端到端科研必会
library(readr); library(dplyr); library(tidyr); library(stringr)
counts <- read_csv(here::here("assets/data/pika_rnaseq_counts.csv"),
                   show_col_types = FALSE)
raw <- read_csv(here::here("assets/data/pika_rnaseq_metadata_raw.csv"),
                show_col_types = FALSE, trim_ws = FALSE)
dir.create(here::here("data"), showWarnings = FALSE)
meta_clean <- raw |>
  mutate(sample_id = sample_id |> str_trim() |> str_replace("^H-", "H"))
expr_long <- counts |>
  pivot_longer(cols = -c(gene_id, gene_name),
               names_to = "sample_id", values_to = "count") |>
  left_join(meta_clean, by = "sample_id")
write_csv(expr_long, here::here("data/expr_long.csv"))
qc <- tibble(
  check = c("samples_in_sheet", "matched_samples", "unmatched_meta",
            "unmatched_counts", "joined_rows"),
  value = c(nrow(meta_clean),
            sum(meta_clean$sample_id %in% names(counts)),
            anti_join(meta_clean, tibble(sample_id = names(counts)[-(1:2)]), by = "sample_id") |> nrow(),
            anti_join(tibble(sample_id = names(counts)[-(1:2)]), meta_clean, by = "sample_id") |> nrow(),
            nrow(expr_long)))
write_csv(qc, here::here("data/join_qc.csv"))

常见错误

QC 表只写「成功」两个字。要写数字：匹配 12/12、未匹配 0/0、行数 24 000。可复核的 QC 才有意义。

科研任务：expr_long.csv 与 join_qc.csv

把本章操作串成 R/07_join.R，产出两份交付物。

  1. 诊断：用 anti_join() 两个方向各跑一次，列出全部不匹配（应为 3 + 3）。
  2. 清洗：str_trim() + str_replace("^H-", "H")；再 anti_join 必须为 0。
  3. 连接：长表 left_join 样本信息；行数 24 000 不变、group 零 NA。
  4. 交付：导出 data/expr_long.csv 与 data/join_qc.csv（5 项数字）。

检查点

  • QC 表数字与脚本输出逐位一致：12 / 12 / 0 / 0 / 24000。
  • 随机抽一个 gene_id，在 counts 与 expr_long 里的 count 完全相同。
  • 删掉清洗两行再跑：行数不变但 group 出现 3 个 NA——这就是「静默丢样本」的现场。

常见错误

Error in `left_join()`: Join columns must be present in data. ✖ Problem with `by`.

病因：by 里写的键名在某一侧不存在（如 sample vs sample_id）。

修复：names() 核对两侧键名；键名不同就用 by = c("a" = "b")。

预防：连接前先打印两侧 names()——键是连接的唯一契约。

Error: `by` must be a (named) character vector, list, or NULL.

病因：by = sample_id 没加引号——R 先去找名为 sample_id 的对象，而不是列名。

修复：by = "sample_id"。

预防：join 的 by 参数永远写字符串。

Warning: Detected an unexpected many-to-many relationship between `x` and `y`. ℹ Row 3 of `x` matches multiple rows in `y`.

病因：右表键有重复（同一 ID 录了两次）——连接会复制行，n 虚增。

修复：count(y, key) 找重复；去重或用聚合后的唯一键表。

预防：连接前对右表做键唯一性检查（anyDuplicated()）。

更多同类报错见 R 代码急救室。

连接是分析的一部分。丢 3 个样本不是「技术细节」——它把对照组的 n 从 6 变成 5，直接改变功效与结论。所以连接 QC 必须出现在方法与补充材料里：匹配 12/12、未匹配 0/0、行数 24 000。

清洗规则、连接、QC 全部在 07_join.R 里；换一批样本表，改的是规则而不是手改 ID。原始 metadata_raw.csv 保持不动——它是数据证据。

Sample identifiers were trimmed of whitespace and harmonised (H-5/H-6 to H5/H6) before joining the long-format count table to the sample sheet; all 12 samples matched bilaterally (anti-join = 0 on both sides), and the joined table retained 24,000 gene-by-sample rows with no missing group labels.

中文：连接前对样本编号去除首尾空格并统一连字符（H-5/H-6 → H5/H6）；12 个样本双向全部匹配（两侧 anti-join 均为 0），连接表保持 24 000 个「基因 × 样本」行且分组信息无缺失。

小结

宽表用 pivot_longer 转长表；连接前 anti_join 双向查不匹配（先看丢没丢）；键清洗写在脚本里；join 后用行数、NA 数、反方向 anti_join 三条对账。QC 表写数字，不写「成功」。
