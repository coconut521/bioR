让分析可复现：Quarto、renv 与项目交付

「把你现在的分析发我，我换台电脑也能跑」——这是导师的要求，也是科研的最低交付标准。

本章科研问题：合作者拿到项目后，如何从原始数据一键重跑所有图、表与报告？

120–150 MIN前置 ch13数据 前面所有交付物交付 report.html · renv.lock · 项目快照

学习目标

  • 说清一次分析包应包含什么：原始数据、脚本、图/表、报告、环境锁、运行说明。
  • 写 Quarto 报告骨架：chunk、label、params 参数化数据路径。
  • 用 session_info.json 记录 R 与关键包版本。
  • 把「一键重跑」写成可执行步骤（build-all → render → validate）。
  • 知道绝对路径、手改图、缺版本记录为什么会让复现失败。

前置：第 13 章；数据：ch01–ch13 全部交付物；交付：report.html、renv.lock、项目快照。

可复现不是「再跑一遍看看」——它是证据链：原始数据不动、脚本是唯一入口、图由代码生成、环境有锁文件、运行有说明。这一章把前面十三章的交付物收进一个项目：数得清、跑得动、交得出去。

1. 项目盘点：脚本、数据与图都能被数出来

交付前先做一次「资产盘点」：章节脚本多少、示例多少、数据文件多少、图多少。数字对得上，说明项目结构完整；数字变了，说明有人手滑加了文件或删了产物。

示例 1：脚本与示例盘点

list.files交付前检查
scripts <- list.files(here::here("assets/scripts"), pattern = "\\.R$")
examples <- list.files(here::here("tools/examples"), pattern = "\\.R$")
c(chapter_scripts = length(scripts), examples = length(examples))
head(scripts, 3)
R console
chapter_scripts        examples 
             18              94 
[1] "ch01.R" "ch02.R" "ch03.R"

逐行解释

  • 第 1–2 行：here::here() 从项目根出发——换机器、换用户名都成立。
  • 第 3 行：18 个章节脚本 + 全部示例脚本；数字与课程大纲一致。
  • 第 4 行：脚本命名 chNN.R，下载与执行都用同一个入口。

常见错误

用 setwd("C:/Users/.../bioR") 写死路径：合作者第一行就报错。所有路径都从 here() 出发。

示例 2：数据与图盘点

资产清单结构检查
data_files <- list.files(here::here("assets/data"))
figures <- list.files(here::here("assets/figures/chapters"), pattern = "\\.svg$")
c(data_files = length(data_files), chapter_figures = length(figures))
R console

             11              18

逐行解释

  • data_files = 11：9 个教学数据 + 数据字典 + manifest——每个都有出处。
  • chapter_figures = 12：注册表里的图全部落盘为 SVG。
  • 用途：交付前跑一次，数字对得上才打包；清单还可以写进 README。

常见错误

把中间产物（临时 CSV、旧版本图）混进 data/ 与 figures/。原始数据目录只放原始文件；产物由脚本生成、可整目录删除重建。

2. Quarto 骨架：params 与 chunk

报告是可执行的文档：代码块真的运行，结果直接嵌入。params 把数据路径参数化——换一批数据只改参数，不改正文。每个 chunk 用 #| label 命名，便于交叉引用与排错。

示例 3：写一个 18 行的 report.qmd 骨架

Quarto · params科研必会
library(readr)
qmd <- c(
  "---",
  "title: \"Pika hypoxia study - reproducible report\"",
  "format: html",
  "params:",
  "  data_dir: \"assets/data\"",
  "---",
  "",
  "```{r}",
  "#| label: setup",
  "library(readr); library(dplyr)",
  "pika <- read_csv(file.path(params$data_dir, \"pika_physiology.csv\"),",
  "                 show_col_types = FALSE)",
  "```",
  "",
  "```{r}",
  "#| label: tbl-qc",
  "nrow(pika); sum(is.na(pika$hemoglobin_g_l))",
  "```"
)
dir.create(here::here("reports"), showWarnings = FALSE)
writeLines(qmd, here::here("reports/report.qmd"))
length(readLines(here::here("reports/report.qmd")))
R console
[1] 18

逐行解释

  • YAML：title / format / params——参数化数据目录。
  • setup chunk：file.path(params$data_dir, ...) 拼路径；label 便于报错定位。
  • tbl-qc chunk：报告里的数字直接来自代码，不是手抄。
  • 第 21 行：18 行落盘——骨架可提交、可渲染（需本地安装 Quarto）。

常见错误

在报告里手写「n = 60」而不是用 inline code——数据一变，报告就撒谎。所有数字都来自代码。

3. 环境快照：session_info.json

同样的代码在不同版本的包上可能给出不同结果。环境快照记录 R 版本、平台与关键包版本——比截图可靠，比口述可查。完整项目用 renv::snapshot() 生成 renv.lock；轻量项目至少写一份 session_info.json。

示例 4：生成 session_info.json

sessionInfo · JSON科研必会
library(jsonlite)
info <- list(
  r_version = R.version.string,
  platform = R.version$platform,
  packages = list(
    readr = as.character(packageVersion("readr")),
    dplyr = as.character(packageVersion("dplyr")),
    ggplot2 = as.character(packageVersion("ggplot2"))
  )
)
dir.create(here::here("reports"), showWarnings = FALSE)
write_json(info, here::here("reports/session_info.json"),
           pretty = TRUE, auto_unbox = TRUE)
names(info)
R console
[1] "r_version" "platform"  "packages"

逐行解释

  • 第 2–9 行：R 版本、平台、三个核心包版本——JSON 结构清晰。
  • 第 11–12 行：写文件（pretty 缩进、auto_unbox 单值不套数组）。
  • 第 13 行：三个顶层字段——文件与代码一致。

常见错误

只记录「R 4.x」。版本要精确到补丁号与包版本；否则半年后复现时根本不知道差在哪。

4. 一键重跑与运行说明

交付物的最后一块是 README：五步之内能跑起来。步骤要可复制粘贴、不含绝对路径、顺序确定。本章把 report.qmd、session_info.json 与 README_run.md 一起放进 reports/。

示例 5：README_run.md 五步运行

交付说明科研必会
readme <- c(
  "# How to rerun this project",
  "",
  "1. Open bioR.Rproj (or set the working directory to the project root).",
  "2. Restore packages: renv::restore()  (lockfile recorded at first snapshot).",
  "3. Rebuild data and figures: bash tools/build-all.sh",
  "4. Render the report: quarto render reports/report.qmd",
  "5. Check outputs: node tools/validate.mjs",
  "",
  "All paths are relative to the project root; no absolute paths appear in scripts."
)
dir.create(here::here("reports"), showWarnings = FALSE)
writeLines(readme, here::here("reports/README_run.md"))
file.exists(here::here(c("reports/report.qmd", "reports/README_run.md",
                         "reports/session_info.json")))
R console
[1] TRUE TRUE TRUE

逐行解释

  • 五步：打开项目 → 恢复环境 → 重建数据/图 → 渲染报告 → 校验输出。
  • 每步都是命令，不是描述；合作者可以逐条粘贴。
  • 第 14 行：三份报告资产齐备（TRUE × 3）。

常见错误

README 写「先运行脚本再打开报告」却没写脚本名。步骤必须具体到文件与命令。

科研任务：可交付的分析包

把本章操作串成 R/14_report.R，产出交付物。

  1. 盘点：脚本、数据、图数量对账（18 / 11 / 12）。
  2. 报告：reports/report.qmd 含 params 与至少 3 个 chunk；renders HTML。
  3. 环境：session_info.json（或 renv.lock）；写清 R 与核心包版本。
  4. 说明：README_run.md 五步之内可跑；全部相对路径。

检查点

  • 删除 figures/ 与 data/ 的产物后，一键重跑能全部重建。
  • 报告里的每个数字都能在代码中找到来源。
  • 换一台电脑按 README 五步走，输出一致。

常见错误

Error: Quarto executable not found. Please install Quarto at https://quarto.org/docs/get-started/

病因：安装了 quarto R 包但没装 Quarto CLI。

修复：装 Quarto 并重启 RStudio；quarto::quarto_path() 检查。

预防：README 写清外部依赖（Quarto、Node、R）。

Error in file(file, "rt") : cannot open the connection In addition: Warning message: cannot open file 'data/raw.csv': No such file or directory

病因：工作目录不是项目根（双击 .R 而不是打开 .Rproj）。

修复：用 here() 定位；RStudio 里 Session → Set Working Directory → Project Root。

预防：脚本只用相对 here() 路径；README 第一步就写「打开项目」。

Error: failed to retrieve package 'readr' from CRAN (offline or unavailable)

病因：renv::restore() 时网络不可用或镜像配置错误。

修复：配置国内镜像 / 使用本地缓存；离线环境用 renv 缓存迁移。

预防：renv.lock 与缓存一起备份；README 写镜像设置。

更多同类报错见 R 代码急救室。

可复现不是附加项，是结果可信的一部分。同一份代码在不同环境给出不同结果时，读者无法判断哪个是对的——除非环境被锁定、路径可移植、每一步都有记录。把「能跑」写进交付清单，与 p 值同等重要。

本章本身就是复现的示范：数据由 generate-data.R 生成、图由注册表渲染、示例输出由 check-examples.R 硬校验、站点由 validate.mjs 把关——没有一步靠手改。

All analyses are scripted in R and can be rebuilt from raw data with a single pipeline (tools/build-all.sh); the report is rendered from reports/report.qmd with parameterised data paths, and the computational environment is recorded in reports/session_info.json (R version, platform, and versions of readr, dplyr and ggplot2).

中文：全部分析以 R 脚本实现，可由原始数据经单一管线（tools/build-all.sh）重建；报告由 reports/report.qmd 以参数化数据路径渲染；计算环境记录于 reports/session_info.json（R 版本、平台及 readr、dplyr、ggplot2 版本）。

小结

可复现交付五件套：原始数据（只读）+ 脚本（唯一入口）+ 图/表（代码生成）+ 报告（params/chunk）+ 环境锁与运行说明。盘点数字、锁定版本、相对路径、五步 README——缺一件，合作者就可能跑不起来。
