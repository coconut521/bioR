多变量与聚类：PCA、热图与样本分群

PCA 第一轴把样本分成两堆——是处理效应，还是建库批次？在解释任何「分群」之前，先看设计表。

本章科研问题：12 个 RNA-seq 样本，PCA 第一轴分离的是低氧处理，还是测序批次？

120–150 MIN前置 ch07 · ch10数据 counts 2000×12交付 fig_pca.svg · fig_heatmap.svg

学习目标

  • 把 counts 转成 logCPM，理解为什么不能直接对原始 counts 做 PCA。
  • 用 prcomp() 做 PCA，读方差解释比例与样本得分。
  • 按 group 与 batch 着色，识别「完全混杂」的图形证据。
  • 画高变基因热图，理解行标准化与聚类距离。
  • 知道无监督分析只能生成假设，不能证明处理效应。

前置：第 7、10 章；数据：pika_rnaseq_counts.csv、pika_rnaseq_metadata_clean.csv；交付：fig_pca.svg、fig_heatmap.svg。

12 个样本：C1–C6 对照、H1–H6 低氧。看设计表会发现一个致命事实：对照全在 batch1，低氧全在 batch2。因此 PCA 上「两组分开」既可能是处理，也可能是批次——本章的任务是看懂这个混杂，而不是把它解释成生物学发现。

1. 从 counts 到 logCPM：先让基因可比

原始 counts 的方差随均值增长，高表达基因会支配 PCA。先过滤低表达基因、算归一化因子，再做 logCPM 变换；这样样本间比较才不被文库大小和表达量级扭曲。

示例 1：过滤、归一化与 logCPM

edgeR先变换
suppressPackageStartupMessages({
  library(readr); library(dplyr); library(tibble); library(edgeR)
})
counts <- read_csv(here::here("assets/data/pika_rnaseq_counts.csv"), show_col_types = FALSE) |>
  column_to_rownames("gene_id")
meta <- read_csv(here::here("assets/data/pika_rnaseq_metadata_clean.csv"),
                 show_col_types = FALSE)
mat <- as.matrix(counts[, meta$sample_id])
y <- DGEList(counts = mat, group = meta$group)
keep <- filterByExpr(y, group = meta$group)
y <- y[keep, , keep.lib.sizes = FALSE]
y <- calcNormFactors(y)
lcpm <- cpm(y, log = TRUE)
data.frame(
  genes = nrow(counts),
  kept = sum(keep),
  samples = ncol(lcpm),
  min_logcpm = round(min(lcpm), 2),
  max_logcpm = round(max(lcpm), 2)
)
R console
  genes kept samples min_logcpm max_logcpm
1  2000 1996      12       1.75      12.96

逐行解释

  • 2000 → 1996：过滤掉 4 个低表达基因；保留的基因才参与结构分析。
  • 12 个样本：列顺序严格按样本表取，避免列名错位。
  • logCPM 1.75–12.96：量级被压缩，样本间比较不再被文库大小支配。

常见错误

直接对原始 counts 做 PCA：方差与均值强相关，第一轴往往只是「测序深度/高表达基因」，不是生物学结构。

2. PCA：方差解释与样本位置

对 12 个样本 × 1996 个基因的 logCPM 矩阵做 PCA（scale. = TRUE）。PC1 与 PC2 解释的方差比例决定这张图能承载多少信息；样本得分则给出分群。

示例 2：PC1/PC2 方差与组中心

prcomp方差解释
suppressPackageStartupMessages({
  library(readr); library(dplyr); library(tibble); library(edgeR)
})
counts <- read_csv(here::here("assets/data/pika_rnaseq_counts.csv"), show_col_types = FALSE) |>
  column_to_rownames("gene_id")
meta <- read_csv(here::here("assets/data/pika_rnaseq_metadata_clean.csv"),
                 show_col_types = FALSE)
mat <- as.matrix(counts[, meta$sample_id])
y <- DGEList(counts = mat, group = meta$group)
y <- y[filterByExpr(y, group = meta$group), , keep.lib.sizes = FALSE]
lcpm <- cpm(calcNormFactors(y), log = TRUE)
pca <- prcomp(t(lcpm), scale. = TRUE)
var <- round(100 * pca$sdev^2 / sum(pca$sdev^2), 1)
cent <- aggregate(pca$x[, 1:2], by = list(group = meta$group), mean)
cm <- cent[cent$group == "control", c("PC1", "PC2")]
hm <- cent[cent$group == "hypoxia", c("PC1", "PC2")]
data.frame(
  PC = c("PC1", "PC2"),
  variance_pct = var[1:2],
  control = round(as.numeric(cm), 1),
  hypoxia = round(as.numeric(hm), 1)
)
R console
   PC variance_pct control hypoxia
1 PC1         12.8   -15.1    15.1
2 PC2          9.7    -0.1     0.1

逐行解释

  • PC1 = 12.8%：两组的 PC1 中心相差约 30 个单位（−15.1 vs +15.1）；分群很明显。
  • PC2 = 9.7%：PC2 中心几乎相同（−0.1 vs 0.1），不承载组间差异。
  • 解释边界：因为 group 与 batch 完全重合，PC1 的分离不能归因于处理；这是本章的核心判断。

常见错误

看到 PCA 分开就写「处理导致表达谱明显改变」。先看设计表：若处理与批次完全重合，只能说「处理/批次混合效应」。

3. 画 PCA 图：颜色与形状必须能回答设计问题

PCA 图至少有三种标记：颜色、形状、分组椭圆。这里用颜色区分 group、形状区分 batch；当两种标记完全重合时，混杂一眼可见。

示例 3：fig_pca.svg

ggplot2交付物
suppressPackageStartupMessages({
  library(readr); library(dplyr); library(tibble); library(edgeR); library(ggplot2)
})
counts <- read_csv(here::here("assets/data/pika_rnaseq_counts.csv"), show_col_types = FALSE) |>

  theme_classic(base_size = 9)
dir.create(here::here("figures"), showWarnings = FALSE)
ggsave(here::here("figures/fig_pca.svg"), p, width = 89, height = 70, units = "mm")
data.frame(
  file = "figures/fig_pca.svg",
  exists = file.exists(here::here("figures/fig_pca.svg")),
  PC1_pct = var[1], PC2_pct = var[2]
)
R console
                 file exists PC1_pct PC2_pct
1 figures/fig_pca.svg   TRUE    12.8     9.7

逐行解释

  • scores：样本得分与元数据按 sample_id 连接；顺序不靠记忆。
  • 颜色 + 形状：group 与 batch 一一对应，图上一眼看出完全混杂。
  • 轴标签带方差：PC1 (12.8%)、PC2 (9.7%)，读者知道这张图解释了多少信息。

常见错误

只按 group 着色，不标 batch；读者会自然把分群解释成处理效应。PCA 图的设计表信息必须画进去。

4. 热图：高变基因的模式

热图选前 60–500 个高变基因，按基因做 z-score；样本聚类常与分组一致，但同样受批次驱动。热图回答「哪些基因一起变」，不回答「为什么变」。

逐行解释

  • top 500：按基因方差排序取前 500；行太多会看不清，太少则不稳定。
  • annotation_col：样本列注释 group 与 batch；两个注释条完全同色。
  • 聚类：列聚类常把 6 vs 6 分开；这仍然不能区分处理与批次。
  • SVG 输出：pheatmap 不直接写 SVG，用 svglite 设备绘制 gtable。

常见错误

热图不标样本注释、不说明 z-score 是按行还是按列；或把聚类顺序当成「样本亲缘关系」。聚类只是距离算法的结果。

5. 聚类：分组一致≠处理有效

层次聚类把样本分成两簇。把簇标签与 group、batch 交叉列表，会发现每一簇恰好 6 个对照/6 个低氧，也恰好 6 个 batch1/6 个 batch2——同一个事实的两种说法。

示例 5：hclust 聚类与设计交叉表

hclust混杂检查
suppressPackageStartupMessages({
  library(readr); library(dplyr); library(tibble); library(edgeR)
})
counts <- read_csv(here::here("assets/data/pika_rnaseq_counts.csv"), show_col_types = FALSE) |>
  column_to_rownames("gene_id")
meta <- read_csv(here::here("assets/data/pika_rnaseq_metadata_clean.csv"),
                 show_col_types = FALSE)
mat <- as.matrix(counts[, meta$sample_id])
y <- DGEList(counts = mat, group = meta$group)
y <- y[filterByExpr(y, group = meta$group), , keep.lib.sizes = FALSE]
lcpm <- cpm(calcNormFactors(y), log = TRUE)
hc <- hclust(dist(t(lcpm)), method = "average")
cl <- cutree(hc, k = 2)
tab <- table(cluster = cl, group = meta$group)
bt <- table(cluster = cl, batch = meta$batch)
data.frame(
  cluster = 1:2,
  control = as.integer(tab[, "control"]),
  hypoxia = as.integer(tab[, "hypoxia"]),
  batch1 = as.integer(bt[, "batch1"]),
  batch2 = as.integer(bt[, "batch2"])
)
R console
  cluster control hypoxia batch1 batch2
1       1       6       0      6      0
2       2       0       6      0      6

逐行解释

  • cluster 1 = 6 control = 6 batch1；cluster 2 = 6 hypoxia = 6 batch2。
  • 完全重合：聚类结果与 group、batch 都 100% 一致；无法归因。
  • 正确结论：样本结构由「处理+批次」共同决定；要分离二者必须重新设计（每组跨批次）。

常见错误

聚类后直接命名「低氧型样本」「对照型样本」并写进论文。聚类标签是算法产物；先与设计表交叉，再决定能说什么。

科研任务：样本结构报告

把本章操作串成 R/17_multivariate.R，产出两张图与一段结构判断。

  1. 变换：过滤低表达、归一化、logCPM；记录保留基因数。
  2. PCA：PC1/PC2 方差、样本得分；按 group 与 batch 双重标记。
  3. 热图：前 500 高变基因 + 样本注释；按行 z-score。
  4. 交叉表：聚类簇 × group、簇 × batch；判断是否完全混杂。
  5. 交付：figures/fig_pca.svg 与 figures/fig_heatmap.svg；报告中写「不能分离」的理由。

检查点

  • PCA 图同时标 group 与 batch；轴标签含方差百分比。
  • 热图注明 z-score 方向与前 500 基因的选择规则。
  • 结论没有把「分群」写成「处理显著改变表达谱」。

常见错误

Error: 'assets/data/does_not_exist.csv' does not exist in current working directory: 'C:/Users/Choi/Documents/ZCode/bioR'.

病因：相对路径按当前工作目录解析，counts 文件不在那里。

修复：用 here::here("assets/data/…") 定位；file.exists() 先确认。

预防：全项目用 here()，不 setwd()。

Error: non-conformable arguments

病因：矩阵乘法维度不匹配，常见于忘记 t() 转置样本×基因矩阵。

修复：dim() 核对；PCA 输入应是样本 × 基因（t(lcpm)）。

预防：进入 prcomp 前打印 dim()。

Error: Can't select columns that don't exist. ✖ Column `body_mass` doesn't exist.

病因：样本表列名拼错，按列选择时失败。

修复：用 any_of() 或核对 names；counts 列必须与 sample_id 完全一致。

预防：join/select 前先 intersect(names(x), meta$sample_id)。

更多同类报错见 R 代码急救室。

无监督分析先看结构，不先看分组。PCA/聚类告诉你样本如何相似，不告诉你为什么相似。把 group 与 batch 同时画进图里，是判断「能不能解释」的最低要求；完全重合时，任何组间差异都无法归因。

本章的 PCA 与热图都由脚本生成；样本顺序来自 meta$sample_id，不依赖文件名排序。图与交付物可以在清空 figures/ 后由示例脚本重建。

Expression structure was explored by principal component analysis of logCPM values (filterByExpr, TMM normalisation, prcomp with scaling); PC1 and PC2 explained 12.8% and 9.7% of variance, and hierarchical clustering of Euclidean sample distances separated the two groups. Because treatment and sequencing batch were completely confounded in this design, the separation cannot be attributed to hypoxia.

中文：用 logCPM 的 PCA 探索表达结构（filterByExpr、TMM 归一化、prcomp 标准化）；PC1/PC2 解释 12.8%/9.7% 方差，样本欧氏距离的层次聚类把两组分开。由于处理与测序批次在本设计中完全重合，这种分离不能归因于低氧。

小结

多变量分析三步：先变换（logCPM）、再做无监督结构（PCA/热图/聚类）、最后回到设计表判断混杂。PC1 分开不等于处理有效；聚类一致不等于因果。图里必须同时出现 group 与 batch。
