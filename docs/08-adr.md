# 08 · 架构决策记录（ADR）

每条决策记录：背景、决定、代价、替代方案。默认状态为「已接受」；若后续变更，追加新 ADR，不修改历史结论。

---

## ADR-001 · 纯静态、零运行时依赖、`file://` 可用

**背景**  
参考站 `cpp_website/v2` 的核心约束是双击 HTML 即可使用，无服务器、无 CDN、无构建产物。R 教学站如果引入框架或后端，会破坏离线分发与长期可维护性。

**决定**  
站点为纯静态 HTML/CSS/JS；不使用 ES modules、`fetch()`、Web Worker、CDN、webfont、外部图片；所有数据以 `window.BIOR_*` 全局加载。

**代价**  
- 无法在运行时读取大文件或调用 R；
- 搜索/索引需要构建期生成；
- 组件状态管理需要手写；
- 数据文件体积受 HTML/JS 加载方式限制。

**替代方案**  
- Next/Vite + JSON 数据：开发体验好，但需要构建与服务器，违背离线双击；
- 后端 API + R 执行：能力强，但部署、并发、安全、隐私成本高。

**结论**  
接受。离线可分发是本项目的核心价值；构建期脚本足以解决数据与图的问题。

## ADR-002 · 沿用 v2 的纸墨编辑设计，品牌色改为 R 蓝 + 苔绿

**背景**  
v2 用纸/墨底、细线、留白、紫色强调，形成「编辑部正文 + 代码实验台」的识别度。直接复制紫色会与 C++ 站混淆；R 有明确的品牌蓝。

**决定**  
保留 v2 的排版、栅格、封面、右栏、Listing、学习地图骨架；主强调色改为 R 蓝 `#23629e`，苔绿 `#3f6b4f` 表示生物/完成状态；红色只给错误。

**代价**  
- 需要重新校准对比度与深色模式；
- 不能直接复用 v2 的 CSS 变量名（避免语义错位）；
- 部分组件需要重新调色。

**替代方案**  
- 完全复制紫色：省事但品牌错位；
- 使用绿色为主：更像生态站，但链接/进度对比度不足。

**结论**  
接受。蓝 + 绿在纸底上可读性和学科指向都更好。

## ADR-003 · 连续科研主线 + 模拟教学数据

**背景**  
分散的语法示例无法让学习者建立「从实验记录到论文」的完整心智模型。真实数据又涉及隐私、许可与可复现性。

**决定**  
设计一条虚构的「高原鼠兔低氧适应」课题，贯穿 18 章；所有数据由 `generate-data.R` 固定种子模拟生成；网页明确标注「教学模拟，不构成科研/临床结论」。

**代价**  
- 需要维护数据生成与字典；
- 模拟数据的生物学细节必须可信；
- 不能直接用于真实论文。

**替代方案**  
- 每章独立小数据：简单，但无累积感；
- 使用真实公开数据：真实，但许可、下载、版本、隐私复杂。

**结论**  
接受。教学优先；模拟数据可完全控制缺失、批次、删失、DE 等教学点。

## ADR-004 · 18 章 = 14 核心 + 4 进阶

**背景**  
R 生物统计覆盖面极广；若把所有内容塞进主线，课程会变成手册。目标用户包括本科生、研究生和实验人员，基础差异大。

**决定**  
核心 14 章覆盖「项目 → 数据 → 可视化 → 推断 → 可复现报告」；进阶 4 章（混合模型、生存、多变量、RNA-seq）独立选修。每章 60–180 分钟。

**代价**  
- 进阶内容不能服务所有用户；
- 需要清晰的前置提示；
- 总内容量仍然很大。

**替代方案**  
- 12 章全部必修：更紧凑，但统计深度不足；
- 30 章百科：覆盖全，但无法完成。

**结论**  
接受。14 章是一学期可交付的最小完整研究闭环。

## ADR-005 · tidyverse 主轨 + base R 对照轨

**背景**  
生物医学 R 用户大量使用 tidyverse；但真实项目、旧脚本、包文档中 base R 无处不在。只教管道会导致「看不懂别人的代码」。

**决定**  
主线用 `dplyr`/`tidyr`/`ggplot2` + 原生管道 `|>`；每个关键动作给 base R 对照（`aggregate`、`tapply`、`[` 等）；速查表同时列两种写法。

**代价**  
- 每章内容增加约 10–15%；
- 初学者可能感到两套语法负担；
- 需要明确「先学哪套」。

**替代方案**  
- 只教 tidyverse：上手快，但迁移能力差；
- 只教 base R：基础扎实，但与生态脱节。

**结论**  
接受。对照轨是「能读别人代码」的必要成本。

## ADR-006 · v1 不在浏览器运行 R；输出与图预生成

**背景**  
WebR 可在浏览器跑 R，但体积大、包支持有限、Bioconductor 不可用、首次加载慢；且与 `file://` 零依赖目标冲突。R 图形在浏览器内生成也需要额外渲染路径。

**决定**  
v1 不内置 R 运行时。代码卡提供复制、下载 `.R`、真实输出终端、预渲染图和出版 PDF。可选的 WebR 沙盒放在 `sandbox.html`，Phase 4 评估，不进入主线，不承诺包兼容。

**代价**  
- 用户不能即时改代码看结果；
- 需要明确提示「复制到 RStudio」；
- 示例必须预生成并校验。

**替代方案**  
- 内置 WebR：交互强，但体积/兼容/离线成本高；
- 后端 R 执行：强，但需要服务器与安全治理。

**结论**  
接受。教学站的首要目标是可读、可复现、可离线，而不是在线 IDE。

## ADR-007 · 所有输出与图由脚本生成，网页禁止手写数值

**背景**  
教学站最常见的错误是「预期输出」与真实运行不一致；统计量、p 值、图一旦手写，后续无法维护。

**决定**  
- 每个 Listing 有 `data-example`，对应 `tools/examples/*.R`；
- `render-examples.R` 生成期望输出，`check-examples.R` 比对 HTML；
- 每张统计图在 `tools/figures/registry.R` 注册，由 `render-figures.R` 生成 SVG/PDF；
- 报错原文由 `collect-errors.R` 真实触发；
- 校验失败阻断合并。

**代价**  
- 作者必须写可运行脚本，不能只写 HTML；
- CI 需要 R 环境与包；
- 图/输出更新需要重跑流水线。

**替代方案**  
- 人工校对：成本低，但长期必然漂移；
- 只校验代码不校验输出：仍会漂移。

**结论**  
接受。这是项目可信度的基础，不妥协。

## ADR-008 · 图内英文、正文与图注中文

**背景**  
中文字体在不同系统、SVG、PDF、期刊排版中容易缺失或变形；同时科研图最终通常需要英文标签。

**决定**  
所有统计图的轴、图例、统计标注用英文；网页正文、图注、讲解用中文。出版 PDF 使用嵌入字体的英文字体。

**代价**  
- 中文读者需要理解英文轴标签；
- 图注需要额外解释缩写；
- 与「全中文」的视觉一致性略低。

**替代方案**  
- 图中中文：更亲切，但字体与投稿兼容性差；
- 全英文：不利于初学者。

**结论**  
接受。教学与投稿的双重目标下，英文图 + 中文解释最优。

## ADR-009 · 统计报告以效应量与置信区间为中心

**背景**  
生物医学教学中普遍存在「p < 0.05 即结论」的坏习惯；小样本、多重比较、伪重复会放大问题。

**决定**  
每章统计内容必须报告效应量与 95% CI；p 值只是补充；不显著时解释为「未检测到差异」；多重比较必须校正；设计与 n 先于检验。

**代价**  
- 内容更长，初学者负担更重；
- 需要更多图（CI、分布）；
- 审核更严格。

**替代方案**  
- 传统 p 值教学：简单，但强化错误习惯；
- 纯贝叶斯：更完整，但超出目标用户。

**结论**  
接受。这是「科研判断力」课程的核心差异点。

## ADR-010 · 7 个专栏，每个一个隐喻；速查表 36 张分批

**背景**  
v2 的专题页用「赛道/标本墙/卡盒/雷区」建立记忆点。R 生物站需要覆盖绘图、生信、统计选择、报错、数据、工作台等多个查询场景。

**决定**  
设 7 个专栏：绘图图鉴、生信航线、数据诊所、统计导航、代码急救、数据集标本馆、课题工作台。每个专栏一个隐喻与一种主交互。速查表 36 张，按 P0/P1/P2/P3 分批实现。

**代价**  
- 专栏维护成本高；
- 需要大量交叉链接；
- 36 张速查表内容量巨大。

**替代方案**  
- 只做 2 个专栏：聚焦，但查询需求覆盖不足；
- 做成一个大「资源库」：省页面，但无记忆点、难导航。

**结论**  
接受。专栏是主线之外的「查方法/看反例/做判断」，必须有独立入口。

## ADR-011 · 不镜像外部数据集，只提供教学模拟数据与外部入口

**背景**  
GEO、Ensembl、GBIF、Dryad 等数据许可、体积、版本各异；镜像会带来许可与存储问题，且与离线包体积冲突。

**决定**  
站点只内置模拟教学数据；外部数据只给检索策略、许可提示、引用方式与链接，不自动下载、不镜像。

**代价**  
- 用户不能一键获得真实数据；
- 需要自己处理下载与版本；
- 外部链接可能失效。

**替代方案**  
- 镜像常用数据集：方便，但许可/体积/更新不可控；
- 只给模拟数据：简单，但缺少真实数据体验。

**结论**  
接受。教学数据可控；真实数据由用户按许可自行获取。

## ADR-012 · 无障碍与色盲安全作为默认，不是可选项

**背景**  
生物图常以红绿区分组别；教学站若默认彩虹色，会把坏习惯传给下一代研究者。

**决定**  
默认 Okabe–Ito / viridis；颜色不是唯一编码；所有图有 alt/图注；键盘可操作；reduced-motion 尊重系统；WCAG AA 为目标。

**代价**  
- 设计自由度降低；
- 需要额外的形状/线型编码；
- 图鉴需要解释「为什么不能用彩虹」。

**替代方案**  
- 先做视觉、后补无障碍：通常补不回来；
- 只做基础对比度：不足以覆盖色盲。

**结论**  
接受。教学内容本身就是示范。

## ADR-013 · 开发文档中文、代码标识符英文

**背景**  
目标团队与用户以中文为主；参考站 v2 的开发文档为英文。若全部英文，内容作者门槛高；若全部中文，代码/数据契约易混乱。

**决定**  
设计/开发/作者文档用中文；代码注释、变量名、函数名、数据字段、文件名用英文；站点文案中文。

**代价**  
- 与国际贡献者协作时需要翻译；
- 文档与代码语言切换。

**替代方案**  
- 全英文文档：参考站惯例，但本项目团队不一定适用；
- 全中文含代码：不利于维护。

**结论**  
接受。以当前团队效率优先；未来可补英文摘要。

## ADR-014 · 页面按「研究阶段」组织，不按「功能」组织

**背景**  
功能式导航（基础/进阶/统计/绘图）会让用户不知道「现在该学什么」。科研是一个有顺序的过程。

**决定**  
首页与课程抽屉按 4 个研究阶段组织：准备数据 → 探索与可视化 → 统计推断 → 交付与进阶。查询型专栏独立入口。

**代价**  
- 某些章节跨阶段（如 ch14 报告）；
- 用户找单一函数时需用搜索/速查。

**替代方案**  
- 按难度分级：简单，但无科研叙事；
- 按包分类：像文档，不像课程。

**结论**  
接受。研究阶段是本站的叙事骨架。
